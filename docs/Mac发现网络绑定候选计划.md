# Mac 多设备候选：发现网络绑定

## 目标与范围

为 Mac 多设备被控发现准备独立、可复用的网络绑定边界：明确用户批准的 IPv4 与系统接口 ID、名称、索引、掩码和系统 Wi‑Fi 证据的对应，任何变化或查询异常使绑定永久失效。此增量不打开 socket、不连接产品或 UI、不创建配对或授权，也不修改当前 Windows 或 Mac 正式版。系统报告 Wi‑Fi 只是分类证据，不是物理真实性证明或抗伪装保证。

## 方案

1. 新建独立 `NianLink.MacCandidateDiscovery` 程序集，复用共享 `VerifiedLanBinding` / `DiscoveryNetworkBinding` 的真实批准、私网、唯一地址与已记录 ID/索引/掩码；Mac 多设备候选在后续 Swift 原生桥和产品接入前不引用或启用此功能，普通 Windows 与正式 Mac 不依赖此程序集。
2. 真实工厂仅在 macOS 可调用，内部独自读取网卡和系统证据，不接受调用方提供的地址可信标志、枚举器、系统证据或 `bool`。现有 Swift CLI 是一次性诊断程序，不是可直接用于授权的原生桥；桥接未实现前真实工厂必须失败关闭，不能把诊断输出或测试结果升级为实时批准。
3. 匹配规则要求：所选地址唯一，网卡 ID / ifIndex / IPv4 / 掩码与真实批准映射完全一致，活动状态有效；系统 Wi‑Fi 证据有唯一的 BSD 名和 index，且能与同一接口的系统 ID 或名称对应，不因名称和 .NET 类型就断言物理性。输入要冻结值、限制数量及名称、拒绝重复、索引冲突、异常或非法子网；复查使用相同规则并比较原始快照，任何异常、失效或变化后永久失效。两次系统采样非原子；不保证恶意驱动、并发外部变更或实际发包的原子性。
4. 合成工厂仅供内部测试，产生的句柄始终 `HasLiveNetworkOrigin == false`，无任何方法升级成 live；真实工厂独占系统读取路径，不允许任意回调代替系统证据。下一增量须实现经过独立验证的 Swift C ABI 桥、系统证据采集及 native if_nametoindex，再给真实工厂接入，不得依赖 CLI stdout。

## 候选真实绑定增量（2026-11-12）

在独立候选程序集提供异步真实工厂：只接受真实 `VerifiedLanBinding`，由内部自行调用系统映射和原生桥，冻结 BSD 名、接口 ID/名称/index、IPv4/掩码及状态；不接受外部合成证据或可信标志。仅限本次内测，将已实测桥 dylib 的 SHA 固定在候选程序中并在加载前校验固定路径，摘要不由调用方提供。固定 SHA 不代表签名，加载前后仍存在同权限进程替换文件的 TOCTOU，本次内测明确接受该限制；未来分发须单独处理包签名、可信装载及权限。

工厂创建后订阅系统网络变化事件并再次异步复核，失败即拒绝；使用时以 `IsStillAvailableAsync` 在锁外重新调用系统采样，不缓存成功，任一变化、异常、超时、取消或事件立即永久撤销。导出撤销令牌供后续传输中止；调用者不得只依据来源标志或旧结果发送。并发复核保守失效，迟到结果不得复活；原生任务即使超时，其缓冲和库仍由在途线程持有至返回或进程退出。合成测试不得升级为 live，注入仅编入隔离测试程序集，不连接产品 UI、socket 或正式版。

先编写失败测试，覆盖来源、首次/连续复核、快照变化、异常、超时、取消、事件/显式撤销、并发和迟到结果，再实现并独立审查。系统通知可能丢失，采样与发送并非原子，无法证明接口物理真实性；未来还需传输层约束接口和收包信息、明确权限、签名及跨设备产品实测。

实现记录：新增测试先因复核组件不存在失败；实现后 136 项 Mac 边界测试通过。`MacCandidateNetworkBinding.CreateForCurrentNetworkAsync` 自行获得经批准的共享绑定、固定摘要桥证据及两次系统采样，注册网络事件后再次验证；通过 `IsStillAvailableAsync` 逐次复核，`RevocationToken` 向使用者提供撤销通知，调用方负责释放绑定。合成对象不能提供共享真实绑定或通过异步 live 复核；旧同步入口继续拒绝。源码候选及项目隔离 Python 检查 26 项通过、1 项跳过，候选收集 796 文件。此次真实绑定源码尚需独立审查，尚未在 Mac 或候选 App 实测。

绑定允许同一个接口同时有多个不同 IPv4，前提是所选地址唯一映射；候选 responder 对实际回复额外采取更严格的单 IPv4 策略，多地址时拒绝并停止。这是两个层次的约束：后续若调整须同步验证调用方，不能仅靠绑定初次成功推断传输可发送。

## 候选桥签后摘要注入

Mac 实测证实对 dylib ad-hoc 签名会改变文件摘要，因此不能把早期未签名桥的固定摘要用于签后包。候选构建属性 `NianWifiEvidencePinnedSha256` 仅由独立打包链传入本次已签名桥的 SHA，候选程序集编入唯一的元数据；无值时真实绑定失败关闭，非 64 位小写十六进制的值在构建阶段拒绝，运行时再次验证唯一性和格式。不接受 UI、网络或运行时参数提供摘要，也不更改旧版或将摘要称为签名证明。

独立打包链需先在新暂存目录签名桥副本并验证，计算签后 SHA，再构建本次候选并拷贝同一桥至固定加载位置；外层签名不递归重签桥，最终比较包内实际桥与程序集编入值。不同构建的签名字节不假设稳定，每次重新计算；验证缺失、错误、重复、两个摘要交替及增量构建刷新，桥读取前后的路径替换窗口仍保留，独立复审和 Mac 签名实测另行进行。

实现记录：测试先因摘要选择接口不存在而失败；实现后 138 项 Mac 边界测试通过。独立离线构建测试确认摘要 A→B→A→无摘要的增量构建会更新并清除程序集中的值，非法格式构建失败；缺失、重复、非小写和无效值在运行时拒绝。源码候选及隔离检查 26 项通过、1 项跳过，候选收集 798 文件。打包端必须传入实际签后桥摘要并核验最终包；仅完成本代码不表示签名、最终包或 Mac 运行已验证，独立复审待进行。

根据独立复审建议增加正向测试：仅在测试程序集嵌入合成文件摘要，实际文件匹配时通过、改变一个字节后拒绝；还从 responder 项目传入全局摘要并检查它携带的候选依赖 DLL。新增后 Mac 边界测试 139 项通过，两个离线构建测试通过。最终签名包内桥 SHA 与候选程序集的对应验证仍由打包链完成。
