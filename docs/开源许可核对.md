# 年年互联开源许可核对（工作记录）

核对对象是 0.1.9 Windows 内测安装包和其包含的 Mac Apple 芯片内测包，不是对未来版本的通用结论。用户选择了修改后分发也需开源的 GPL 方向；本记录不是法律意见或已经完成合规的证明。不要发布密钥、配对文件、用户配置或私人资料。

## 自有代码许可建议

对确认有权许可的年年互联源代码，可采用 **GPL-2.0-only** 作为项目主许可；保持每个第三方文件及代码片段原有的版权、许可和例外声明。这个选择符合用户要求，但应先核对代码、图标和参考素材的权利来源，不能以项目根许可替换别人已授予的许可。软件作者可以许可自己的代码，不应代表其他版权人作出新的例外或版权声明。

Deskflow 的 OpenSSL 例外只按上游和各文件原有声明保留。是否需要对本项目拥有权利的代码额外授予类似例外，取决于具体代码边界及其与 OpenSSL 的链接方式，不宜未经核查就把例外扩展到全部源码。组件之间通过进程通信也不能自动证明任何组合均不受相应许可约束。修改后的 Deskflow、Qt 和 OpenSSL 的具体组合需按最终分发物与对应文件核对。

## 公开前检查

1. 审核源码对应关系、第三方文件头和图标来源；记录权利人和许可证范围。未确认的资产不要以自己拥有的作品声明。
2. 为当前修改版 Deskflow 准备准确上游源码、补丁、构建/安装脚本、各项依赖版本和许可；在干净环境验证构建或准确记录未能重现的差异，并确认适当的对应源码分发方式。
3. 根据实际 Windows 与 Mac 载荷分别形成版本化清单；检查全部许可、通知、版权和二进制/源码对应关系，保留 Deskflow OpenSSL 例外及其他文件级条款。
4. 分离私有配置和个人资料后再制作待公开源码，扫描路径、证书、令牌、配对文件和历史记录。扫描不保证发现全部隐私信息。
5. 本项目当前安装器是内测物：Windows 未签名、Mac App 未公证；公开分发前在干净设备验证安装并告知实际状态。开源协议检查通过与安装包签名/安全审查是不同事项。
