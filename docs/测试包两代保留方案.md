# 测试包两代保留方案

## 目标与边界

按用户要求，分别保留每种测试包的当前版和上一版，限制测试产物持续增长；这一规则只针对可重建的**测试包**。现用正式安装、现存的设备配对资料、测试资料目录、未提交源码、截图、第三方源码和许可、独立验证证据均不是自动清理对象。旧测试资料须单独审核，不能按日期批量删除。项目维护目录为 `[本机路径已省略]`，该目录不是 Git 仓库，不能据私有仓库提交推断本地未提交内容已备份。

## 已核实的路径关系

- Windows 打包分为普通多设备、发现便携、免文件便携和免文件诊断；安装器是单独的产物。Mac 打包分为发现、免文件、多设备及其他测试模式，Mac 导出组合包也是单独产物。每种模式使用独立的两代记录，不应将不同模式仅按时间排序后合并。
- Windows 发现便携包的 `test-<32位GUID>` 与包中的 `discovery-portable-id.txt`、清单 `runId` 及 D/H 盘 `test-profiles/discovery-portable/test-<GUID>` 启动路径相互关联。`DiscoveryPortablePaths.psm1` 要求输出目录和全新资料目录的 GUID 匹配；`discovery_portable_policy.py` 校验身份与启动命令。重命名为 `current`、`previous` 或复用旧 GUID 会破坏隔离。包到期不代表对应资料可以删除，资料始终独立保留。
- Windows 多设备安装器只接受 `.artifacts/multidevice-windows/test-<GUID>`，并核对候选清单和载荷。Windows 多设备打包器可消费 `.artifacts/mac-export/test-<GUID>`，并校验导出内容。Mac 打包、Mac 导出和安装器也各自生成 GUID 输出。新方案须保持这些物理路径和现有消费者契约。
- 打包入口使用 `BuildArtifactLock.psm1` 的项目构建互斥；覆盖范围仅限明确持锁的调用。任何保留机制须与现有锁协作，并保持正式版与用户资料在其作用域之外。

## 后续设计

1. 在受控测试产物范围内，为每种模式建立清单，记录当前及上一**成功验证**包的实际 GUID 路径、类型与完整性信息；用受限格式检查路径，拒绝越界、重解析点、重复或不匹配的条目。清单不作为软件签名、真实性或许可合规证明。
2. 新包保持唯一 GUID 和唯一配对资料身份。必须先完成该模式全部打包和验证，确认其状态可用，再原子更新对应记录；已存在的当前版和上一版在构建、验证失败时不受影响。Windows 发现包在写入状态文件之后还要通过 `discovery_portable_policy.py`，不能仅凭状态文件存在认定成功。
3. 考虑构建或更新过程中断：明确恢复记录、孤儿输出与部分文件的状态，不将半成品当作当前版；并发运行使用同一构建锁或可证明等效的互斥。清单丢失、损坏、内容不匹配或目标正在使用时，停止并提示，不猜测版本、覆盖或删除。
4. 成功构建期间允许有一个受控候选；实际稳定状态的两代限制需要处理旧包。若不能安全回收已过期的产物，先停止新一轮构建，避免继续产生无界目录；报告具体原因和保留的版本，不扩大到其他目录。容量不足时保留当前及上一成功版并终止，不先删除上一版腾空间。
5. 执行环境此前对删除旧测试文件返回 `blocked by policy`，原因不明。方案不得改变执行策略或通过其他方式绕过这一拦截；在有允许的清理渠道并核对路径、重解析点和占用状态之前，只记录可清理候选，不声称已经腾出空间。对测试过程中专门生成的合成夹具应使用独立临时目录，不能指向旧资料。

## 验收

- 合成测试覆盖每种模式独立保留、首次和第二次发布、第三次容量限制、不同 GUID 与 profile 不变、两代清单读取以及消费者对物理 GUID 路径的校验。
- 在打包、最终验证、清单写入和更新的不同阶段注入失败或中断，验证当前版和上一版仍可用；覆盖恢复后重试、锁竞争、启动中的旧包和空间不足。
- 覆盖清单篡改、路径穿越、父路径与子项链接、重复或未知文件、源目录变更、损坏归档、资料目录混入及正式版路径拒绝；模拟旧包不能回收时禁止持续创建新输出。
- 分别用 Windows 测试包和 Mac 测试包的隔离构建链验证完整路径及既有消费者。合成测试或构建不等于真实设备、正式发行或许可验收。

## 2026-11-16：Windows 受控内测包增量

Windows 普通发现、免文件和诊断打包默认进入各自受控目录：`.artifacts/discovery-portable-managed/discovery`、`fileless` 和 `diagnostics`。每个目录分别记录当前和上一成功候选；创建目录前先记录 pending，完整包校验及最终 discovery policy 成功后才登记。已有两代或存在未完成候选时拒绝继续生成，保留原内容。现用正式版、旧的 `.artifacts/discovery-portable` 和 `test-profiles` 不参与该机制。在 PowerShell 中显式传 `-ManagedRetention:$false` 可使用旧兼容入口，但该入口不提供两代限制。

打包入口先获取项目构建锁，再获取受控目录租约（如适用）及免文件缓存租约；缓存占用或不符合校验时，在预留和创建包目录前退出。独立文件租约用于协调接入该机制的进程，不能防止外部程序或同一用户直接更改文件。两代记录与压缩包、解压包和清单校验不构成签名或完整发行验证。

该机制**不会删除旧包、不会释放历史空间，也不会自动轮换**。如果两代已满，需先核对 `retention.json` 中 `current.id` 和 `previous.id` 与对应目录；当前运行中的程序、正式安装、其他模式以及 `test-profiles` 不可当作旧包处理。在允许的清理渠道中确认且移除了受控目录中对应的上一代目录后，才能显式更新记录。若构建失败留下 pending，也应先检查原因；仅在该 pending 对应目录已经不存在、且其余记录及文件完整时，允许清除这一记录。索引残留、未知文件、包内容变化或链接会使维护操作停止，需先诊断，不能通过猜测版本或清空目录解决。

从项目根目录运行下列维护入口（将 `fileless` 换为 `diagnostics` 或 `discovery` 可维护对应测试包）：

```powershell
pwsh -NoProfile -File .\scripts\maintain-discovery-retention.ps1 -Mode fileless -Action missing-previous -TestingOnly
pwsh -NoProfile -File .\scripts\maintain-discovery-retention.ps1 -Mode fileless -Action missing-pending -TestingOnly
```

以上命令只在对应目录已经不存在时更新索引，**不删除任何包或资料**；不要对仍存在的包运行后误以为空间已释放。旧目录和失败候选是否可删除仍须另行核对，执行环境此前拒绝的删除操作不得换方式绕过。

隔离完整打包验证：免文件与诊断包均核验 524 个 ZIP 文件与清单；免文件负例在隔离源码中故意缺少 policy 必需文件，最终策略拒绝后保留 pending，已有包的 526 个文件摘要不变，重复构建被阻止。最终冻结源码的默认入口再打出第二个诊断包，两代各 526 个文件与索引保持完整，第三次因满额在编译前拒绝且未生成目录。普通发现包在五项研究 gate 的环境值均为 true 时构建成功，515 个 ZIP 文件与清单、四项隔离 DisplayBridge 文件及代表性程序集标记核验通过；非空 DefineConstants 在创建缓存或输出前被拒绝。明确关闭受控的分支只用合成前置材料验证路由，最终增加的索引恢复入口尚未在真实历史包上使用。最终组合 185 项中 183 项通过、2 项跳过；独立复审修复了维护 action 大小写误分支及不可能的 current+previous+pending 状态。验收摘要在 `[本机路径已省略]` 和 `discovery-verification-summary.json`；隔离目录约 4.64 GiB，保留测试包、Mac 托管验证和失败证据。以上均未启动或安装应用，涉及的真实 profile 未创建；完整跨设备验收仍未完成。Mac fileless 测试包的后续管理及限制见下节，其他旧入口仍可能产生新的独立目录。该机制不证明断电恢复或防同用户篡改。

后续安全复审发现索引及状态文件存在重复键折叠风险；已对新登记和旧代复核使用有界、拒绝重复/大小写及 Unicode 同义键的 JSON 快照解析。Windows 定向组合 112 项中 107 项通过、5 项环境跳过；用独立验收工程已有的诊断包复核正常两代仍可读取，满额拒绝，索引及两代各 526 文件不变。既有含歧义字段的异常记录会只读拒绝，不会自动改写或清理。

## Mac 免文件测试包校验

Mac fileless 的包结构、桥、原生证据和使用入口与 Windows 不同，不能套用 Windows 校验器。已只读核对历史包并开发独立校验器，在合成材料中验证正常包、内容/清单/压缩包篡改、身份或桥指纹不一致、路径和链接等负例。校验器现已接入 Mac 受控测试打包；没有更改现有 Mac 测试包和用户资料，也没有删除旧资料。

当前本机未发现与最新源码匹配的 Mac 原生构建证据，可操作的远程连接也未建立；合成校验只能证明所覆盖的文件规则，不能证明完整发行、Mac 原生签名、权限或真实设备行为。历史样包只读核验 ZIP 等格式，但因缺少四份新必需脚本被新校验器按预期拒绝；该样本的旧原生源码摘要与当前源码也不一致。之后在可验证身份的 Mac 独立重建原生助手，再验证完整包及两代机制；若环境不允许删除，不能借记录或替代方式绕开限制。

### 独立候选包一致性检查

`scripts/verify_mac_fileless_candidate.py` 是只读检查工具，仅用于新免文件测试候选，默认接受指定项目 `.artifacts/mac-package/test-<32位小写十六进制标识>`；显式 `--managed-fileless` 时只接受 `.artifacts/mac-package-managed/fileless/test-<标识>`。它检查固定产物、应用和 ZIP 内容及清单、文件类型与 ZIP Unix 权限、候选身份、桥文件摘要、原生证据、明确列出的构建输入和七个原生源码记录是否一致；拒绝链接、重复或含歧义的 JSON 键及 ZIP 名称。ZIP 的本地和中央目录均不得含 extra 字段，这是当前候选格式的严格约束；如果将来打包格式变化，须重新验证后再调整。检查器需要摘要信息之外可独立信任的来源：不能从待检查包自身读取桥或原生证据摘要，再把它们当成独立证据。

在隔离候选上运行示例（将占位内容替换为已经独立核对的值）：

```powershell
python -B scripts/verify_mac_fileless_candidate.py --project-root <项目绝对路径> --candidate <候选目录绝对路径> --version <三段版本号> --bridge-sha256 <独立核对的桥SHA256> --evidence-sha256 <独立核对的原生证据SHA256>
```

工具本身不会建立索引、清理或登记包；受控 Mac 打包入口在持锁下调用它，验证通过后才登记。它不证明全部依赖图完整、程序集内嵌桥指纹、来源可信、Apple 签名或公证、第三方许可合规、可复现构建及 Mac 设备上的运行结果；同一用户同时改写代码、材料和预期摘要，或检查期间发生并发改动，也超出其保证范围。摘要中的 app 和 ZIP 路径须与当前候选目录一致，移动后的包或不包含新必需输入的历史包可能被拒绝。已用合成样本进行自动测试和独立完整脚本验证，真实原生产物及实机验证仍待完成。

独立复审和合成回归覆盖 JSON 规范、原始 ZIP 名称及本地/中央扩展字段等负例；Mac 默认受控最终组合回归 160 项中 158 项通过、2 项因无法创建符号链接而跳过。此工具及测试已纳入源码收集器。合成原生材料明确标记且未交付；在真实原生证据及设备验证前不将合成结果当作完整 Mac 包验收。

### Mac fileless 受控索引

拟在独立 `.artifacts/mac-package-managed/fileless/test-<GUID>` 从构建开始生成候选，不移动旧包或改变它们的绝对路径。先扩展新候选校验器接受明确的受控根；Mac 管理记录独立于 Windows，以项目锁、Mac 管理文件租约及现有共享缓存租约按固定顺序协调。预留 pending 在输出创建前持久记录，独立 verifier 以已核对的外部桥和原生证据摘要检查成功候选后才登记；每代同时记录 ZIP/manifest/解压内容的摘要，历史代只核对自己的记录，不拿当前源码重判。两代满、待处理、未知文件或异常索引时停止；维护仅可清除对应目录已不存在的索引记录，不删除任何文件。

先用显式开关与合成 fixture 覆盖路径、并发、失败、满额、索引恢复和旧入口，再在专用隔离工程使用真实托管构建及明确标注 `SYNTHETIC`、不可部署的伪原生组件验证包格式。保留输入来源、测试记录与原有资料；不启动 app、不创建真实 profile、不进行发布。合成组件及其状态不能视为 Mac 原生构建、签名、公证、设备运行或发行许可通过；只有可信可操作的 Mac 可完成与当前源码匹配的原生重建和实机验收。本增量不绕过执行环境拒绝的旧文件删除，也不声称可以自动释放空间。

Mac fileless+discovery 测试包现默认切至受控目录，显式 `-ManagedRetention:$false` 保留不受两代限制的旧路径；其他 Mac 模式维持原样。真实脚本使用合成原生组件两次成功打包并保留两代，第三次满额拒绝；默认入口复用已满额的合成工程再次验证未新建包。真实 Mac 原生、签名及设备仍待后续验收。摘要与日志已保存在 `docs/测试证据/Mac受控合成验证`；合成工程 `[本机路径已省略]` 约 1.77 GiB，删除时被执行环境策略阻止，仍在磁盘，**不可运行、上传或交付其中的伪原生 App**。

### Mac 免文件测试包的使用和记录维护

`build-mac-test.ps1` 在同时启用 `-DiscoveryTesting -FilelessTesting` 时默认使用独立的 Mac 受控目录；明确传入 `-ManagedRetention:$false` 才走旧测试包目录，旧路径不限制生成数量。其他 Mac 构建模式维持原有路径。现用正式版、Mac 上的独立资料和历史测试包不纳入该目录。两代已满、存在未完成候选或记录异常时会停止构建；**不会自动删除文件，也不会因此腾出磁盘空间**。

下面的命令在项目根目录 `[本机路径已省略]` 的 PowerShell 中运行，仅维护测试包索引，不执行文件删除。运行前须核对受控目录的 `retention.json`、当前包和待处理项；仅当对应的上一代目录或 pending 目录已经不存在、其他记录和当前包通过检查、没有未知文件或链接时，命令才会更新索引。目录仍存在、当前包被改动或记录不完整时应停止并先排查，不要把用户资料、正式版或历史旧目录当作待清理的测试包。

```powershell
pwsh -NoProfile -File scripts/maintain-mac-fileless-retention.ps1 -Action missing-previous -TestingOnly
pwsh -NoProfile -File scripts/maintain-mac-fileless-retention.ps1 -Action missing-pending -TestingOnly
```

分别用于清除已不存在的上一代记录和已不存在的未完成候选记录。它们不会删除、移动或覆盖任何测试包、配对资料及正式安装。默认入口在独立合成工程中验证了两代满额时不新建目录；真实 Mac 原生证据和设备验证尚未完成。
