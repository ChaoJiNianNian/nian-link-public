# 年年互联多设备测试版：使用与已知问题

> 状态：**发布准备资料，尚未完成发布**。本文描述项目内独立测试候选的使用方式及限制，不代表当前源码的所有平台已完成打包、安装或实机验收。现有候选仅供本人内部测试；请勿当作正式版或公开分发。

本轮在独立测试中，归还不确定状态、IPC 断开及迟到回复 51 项通过，模拟网络丢失与停止并发 8 项通过；另有两个 Windows 真实浮窗配合合成后端的竞态反例失败，关闭窗口时可能丢失归还入口。这不是物理断网或真实键鼠测试，不表示自动恢复或安全归还已经完成。

维护源码随后局部修正了另一种误报：键鼠连接断开或断开后重连时，不直接采信先前请求的迟到成功回复。两项真实窗口及客户端配合回环 TLS、合成 IPC 的反例由失败转为通过，相关 Guard 26 项、DeskLink 489 项和 MultiPeerTrust 165 项通过；该检查无法封存远端或原生在途动作，也不能保证检查之后不会断开。上文 Windows 和上一代 Mac 候选在该源码修正之前构建，**不包含这项修复**。

## 测试前准备

1. 保留现用正式版及原有配对资料；准备每台电脑自己的键盘和鼠标，便于需要时在本机操作。
2. 两台设备连接同一个可信局域网。互联网不可用但局域网仍能互通，与设备间局域网断开是两种情况；不应假定断线后能自动恢复。
3. 先正常退出可能同时使用键鼠共享核心的旧测试窗口或其他共享程序，避免进程争用；不认识的进程不要直接结束，不要删除原有资料。
4. 使用以下候选时，要使用其独立测试目录。若所需磁盘、权限或依赖不满足，先停止测试，不要改用正式版目录作为测试资料。

## Windows：本轮测试安装器

本轮安装器仍是本地候选，不是已发布版本。它需要 Windows 10 版本 2004 或更新的 x64 系统、WebView2 Runtime 和匹配的 Visual C++ x64 运行库。安装器只检查运行库的注册记录，不保证检测到的版本可用；如提示缺少依赖，可查阅微软的 [WebView2 运行时说明](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)及 [Visual C++ 运行库下载](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist)。

在隔离测试机器运行测试安装器，根据安装窗口的提示完成安装；安装器使用专用目录和独立的开始菜单分组。安装完成后从该测试版分组打开程序，或勾选创建带构建标识的桌面快捷方式。同一构建会使用自己的独立测试资料，卸载程序不删除这些资料；不同构建之间不会自动迁移配对。

在本机已验证两代候选安装、打开窗口、关闭及卸载；尚未验证其他账号、干净系统、真实配对、归还和断线。未解决的归还风险见下方已知问题。

## Windows：启动历史便携候选

将经核对的 Windows 测试 ZIP 解压到独立文件夹，保留文件结构。用作主控的笔记本双击包内「笔记本-D盘启动.cmd」；用作被控的 Windows 台式机双击「台式机-H盘启动.cmd」。测试资料分别写入脚本指定盘符的独立测试路径。它们不适合没有对应 D 盘或 H 盘的设备，且不应通过改写为正式版路径来绕过限制。

打开后根据本机角色选择「主控电脑」或「被控 Windows」。若启动失败，保留提示内容；现有包在干净 Windows 系统上的运行库依赖仍待验证。

## Mac：启动免文件候选

在满足条件的 Mac 上，将 Mac 测试 ZIP 解压到独立文件夹，打开文件夹并双击「安装并启动.command」。该入口按内测流程在用户目录下准备单独的测试 App 和资料，并在桌面生成带标识的启动入口；它不是正式安装器。已有正式 App、Deskflow 配置和配对资料应保留。

若系统提示开发者工具、Python、程序签名或权限问题，记录原文后停止并排查，不要关闭系统安全保护来强行运行。这个具体候选尚未在 Mac 上完成启动和双机验收，实际首次体验与兼容性仍待验证。

## 发现与免文件配对

具体按钮名称可能随测试候选不同略有差异，以窗口中的实际提示为准。

1. Windows 主控在「设置与权限」选择当前活动局域网，点击「准备主控」。在另一台 Windows 选择「被控 Windows」，或打开 Mac 的独立测试窗口。
2. 被控端进入「发现与配对」，刷新网络，选择当前联网的地址，点击「允许被发现 30 秒」并同意。开放期间，同一局域网里的其他设备可能看到本机名称、系统和键鼠指纹。
3. 主控点击「扫描设备」，选择自己的设备并发起安全配对。被控端收到请求后，只在确认这是自己发起的请求时继续；设备名称本身不能证明身份。
4. 在两台设备上逐字核对两项完整指纹：主控显示的对方键鼠指纹与被控设备本机键鼠指纹；主控本机控制通道指纹与被控端显示的主控控制通道指纹。两项都完全一致后，在两端分别确认；任何一项不一致或无法核对则取消。
5. 等两端提示配对完成，再按提示启动共享或在被控端点击「开始连接」。首次键鼠连接如再次要求核对主控键鼠指纹，仍须与主控连接详情中的完整指纹核对一致后确认。发现设备、配对完成和已连接是不同状态。

免文件配对无需手工传输 JSON。配对资料含控制凭证，不能发送到公开聊天、上传到公开仓库或放入测试安装包。

## 键鼠、画面及归还

两边显示已连接后，在 Windows 主控「设备」页选择目标设备，点击「切换到这台电脑」。尝试操作后，通过界面的「归还主控」或 `Ctrl+Alt+F11` 归还，观察真实键鼠位置和双方状态。使用预览操作时，通过预览窗口的停止操作或归还入口结束；普通切换和预览操作是不同入口。

画面查看与本机画面分享是两个方向的独立开关。例如 Windows 查看 Mac 时，需要 Mac 允许分享本机画面，Windows 打开查看对方画面，并按系统实际提示处理 Mac 屏幕录制权限；反向查看则要在 Windows 允许分享、Mac 开启查看。重新启动 Mac 多设备连接后，本机分享需重新允许；各候选的界面和行为仍待实机复验。

Mac 键鼠、发现与画面可能分别需要局域网、辅助功能、屏幕录制等系统权限。权限应针对系统实际列出的测试 App、Deskflow 或媒体进程核对；若系统要求退出重开，重新打开同一独立测试候选后再检查状态。

## 已知问题和处理

- **安全归还与浮窗**：连接代次、旧焦点事件、停止时重复归还、预览归还误判及浮窗并发等问题仍有待完善或真实设备验证。界面显示不明确或键鼠位置不符合预期时，不要假定已归还或反复切换；先使用各设备自己的键鼠检查状态，并使用可见的归还或停止入口恢复。
- **断线和恢复**：自动恢复、网络中断、设备休眠和异常关闭后是否安全归还尚未完成实机验收。当前网络检查主要观察所批准的本地网卡状态，通信路径断开不一定触发；检测到网络不可用时会停止共享并要求重新确认网络。断网不能保证继续连接；局域网恢复后也不能保证自动重连。
- **搜索不到或没有请求弹窗**：检查两边是否处于同一局域网、是否选中活动网卡、被控发现是否仍在 30 秒开放期，再重新开启发现并扫描。发现记录不等于身份验证。请求丢失及超时等场景仍需验证。
- **配对结果待确认**：不要当成成功或失败，也不要删除测试资料；两边按界面查看未完成的配对并根据实际提示处理。若仍无法判断，停止并保留提示。
- **提示已有 Deskflow 核心运行**：先正常退出已知的旧测试版或共享程序。若仍有冲突，记录提示并核实进程归属；不要随意结束未知进程或改动正式版。
- **画面或控制不可用**：分别核对分享、查看开关与系统权限；授权后仍失败时记录设备、操作和错误。Mac 对应 App 和实际进程的权限、权限重启流程需要进一步验证。
- **多台设备与其他功能**：四台远端并发、共享显示器切屏、全部画面方向、文件/剪贴板等功能与断线异常，不能由单次双机实测推定全部可用。
- **安装与发行**：Windows 新免文件候选已有独立测试安装器，本机安装、两版共存和卸载验证通过；干净系统、实际双机和依赖版本仍待验证。Mac 已取得当前源码的原生构建证据，但新候选的一键安装及实机验收不完整。Deskflow 对应源码、Qt 等第三方依赖和许可、运行库交付、签名与公证仍需核对。

## 发布准备仍需完成

1. 确定实际发布的 Windows 与 Mac 版本并完成对应安装验收；新 Windows 测试入口不要求 D/H 盘，Mac 包仍缺 Deskflow，教程和依赖须按最终载荷核对。
2. 在隔离环境核验包内容、用户数据隔离、依赖和第三方许可，避免把真实配对文件、证书、日志和网络信息装入包或上传。
3. 对实际要发布的包完成安装启动、双机配对、键鼠归还及断线安全验证；如某项未验收，明确列入该版本已知问题。
4. 核对私有 GitHub 仓库与发布附件、记录准确版本和 SHA-256，再发布带测试版标识的版本说明。维护现用正式版不变。
