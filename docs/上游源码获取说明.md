此目录是供审核与集成的独立工具，不是产品程序。Python 3.10 及以上运行，无第三方 Python 包。运行 `python scripts/fetch_upstream_sources.py` 时才联网；不自动运行、安装、编译、解压源码或启动年年互联。工具脚本位于项目 `scripts/` 时，源码默认落在项目 `.artifacts/upstream-sources/source-<随机标识>/`，不会写入现用正式版。

## 操作与验证

在项目根目录运行：

```text
python scripts/fetch_upstream_sources.py
python -B -m unittest discover -s tests -p test_fetch_upstream_sources.py
```

第一条需要网络；第二条是本地合成 HTTP 响应测试，不绑定网络端口、不下载源码。成功时脚本输出 `verified` 路径。四份源码全部通过长度与 SHA-256 后才开始复制到 `verified`，每份复制时再次核验；`verified/manifest.json` 是最后写入的完成标记，**只有脚本成功退出且该文件是完整 JSON、`complete` 为 true 时才视为完整结果**。建议使用前仍按清单重新计算哈希。

失败时不清理目录：`.pending` 可能保留不完整下载；最终复制发生异常时 `verified` 可能存在但没有完整清单，不能当成完整成果。工具不覆盖既有目标、不递归删除任何文件。每次默认使用新的随机目录；如果在受信任环境自行确认目录属于本次失败，可由用户手动清理。完成后 `.pending` 仍保留，因使用复制而非硬链接需要额外磁盘空间；请预留约 230 MB 以上及网络传输余量。

初始地址和重定向只接受 HTTPS 且目标必须在脚本域名白名单。Qt 地址在本机重定向到的 `qt.mirror.constant.com` 已列入允许列表，仍强制核对固定长度和 SHA-256；若官方变更重定向域名，程序会拒绝而不会跳转到其他位置，需要重新核对再修改白名单。网络调用设置 60 秒套接字超时，属于每次网络等待的限制，并非整个下载过程的总时限。每个归档有固定长度上限与最终完整性校验。

目标目录、各既有祖先、临时/最终目录与文件在使用前检查符号链接和 Windows 重解析点；新目录与文件使用排他创建。该设计保护正常使用时的意外覆盖，并非对同一用户权限下的恶意进程并发替换路径提供无条件保证。请在用户可控的本机普通目录运行，不要与其他进程共享或改动本次输出目录。

## 用途和边界

这四份归档、仓库内的补丁与已有许可说明只是对应源码核对材料的一部分，并未证明旧版 Windows 测试核心能够由这些材料重建，也未确认 Mac 核心对应源码，更不能单凭此确认第三方许可义务全部满足。源码获取不包括操作系统开发工具链、Qt 编译产物或其他平台专用依赖；构建须按项目文档分别核对。

原有 `prepare_deskflow_source.py` 是针对旧工程已记录材料路径和历史补丁的离线收集器；本工具输出的 `verified` 目录不是其预期的旧工程根目录，不能直接当作该收集器的输入。后续若要组合两者，须明确映射源码归档及已核验补丁、保留两种来源的完整性测试，不要为了适配而把个人旧工程路径或构建产物提交到仓库。
