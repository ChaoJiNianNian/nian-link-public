# 二进制载荷依赖与许可审查

本记录供项目私有审查，不是法律意见、完整软件物料清单或发行许可结论。以下测试载荷均在独立目录读取或生成，尚未完成空白机安装、实际设备验收；未修改现用正式版和真实配对资料。

## 历史 Windows 便携测试包

对 `NianLink-fileless-portable-windows-internal-test.zip`（2026-11-14 内部候选，SHA-256 `c956fc6af2f87c22220e7dc566357c3d602c5804a2e514060bc7da934cdb32c9`）进行了 ZIP 完整性检查：515 个文件，ZIP CRC 通过。文件名检查未发现许可或第三方通知文件，不能作为发行许可已满足的证明。该检查按文件名筛选，不声称逐字检查每个文件内部内容。

`NianLink.DiscoveryPortable.runtimeconfig.json` 标明自包含 Microsoft.NETCore.App 与 Microsoft.WindowsDesktop.App 10.0.13；deps 标明 Microsoft.Web.WebView2 1.0.4258.31。两个 10.0.13 Windows NuGet 原始包逐条许可和通知已核对；原包的签名验证依赖当前主机的信任和吊销配置，不能替代对发行载荷的逐项审查。WebView2 SDK 依赖和 Windows SDK 分发条件需按最终产物继续核查。

包内 Deskflow 核心、Qt 核心/界面/网络/窗口库及其平台插件、OpenSSL 两个 DLL 的 9 个样本与本机留存副本逐字节 SHA-256 一致；Qt 六个库和插件在本机 Authenticode 检查均显示有效且签名主体为 The Qt Company Oy。六项 DLL 和插件已与固定 SHA-256 的 Qt 官方 6.8.3 MSVC x64 二进制归档逐字节对照一致；归档内 SPDX 的原始 SHA-1 与签名文件不同。对 PE 文件在内存中移除尾部证书、清零校验和及安全目录后，六项归一化 SHA-1 均与 SPDX 记录一致，支持签名前后差异的解释，但不能证明 Qt 实际签名流水线。官方源码发布包与对应 Git 提交的 21,966 个条目逐项一致，发布包另有两项；完整构建配置和许可义务仍需核对。详见[Qt 历史文件来源核验](Qt历史文件来源核验.md)。

Deskflow 核心的 PE 导入包括 `MSVCP140.dll`、`VCRUNTIME140.dll`、`VCRUNTIME140_1.dll`，该 ZIP 未包含这些文件。目标机器必须以受支持的方式满足依赖；已有机器能运行并不证明干净 Windows 可以启动。获取与分发条件以微软的[受支持 Visual C++ Redistributable 下载](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)和[再分发说明](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files)为准，本次未安装或修改系统。

## Qt、OpenSSL 和 Deskflow

历史 Windows 多设备核心与留存对象和静态库隔离重新链接的结果仅有 6 个字节不同，均在 PE 两处时间戳字段；归一这两个字段后整个文件逐字节一致。该结果支持现存链接输入与历史核心的对应，但不证明历史编译时每个源码输入、动态库及完整发行许可；工具和证据见 `tests/experiments/DeskflowPeProvenance/`。


已保存固定 QtBase 6.8.3 与 OpenSSL 3.5.9 原始归档；132 份上游许可、归因及被引用许可文本逐文件与归档原文、SHA-256 对照一致。上游源码包含不同文件及不同许可，不意味着最终发行物使用全部组件，也不能把采集文本当作实际载荷完整许可清单。Qt 的选择与义务须按实际动态链接、模块、构建选项及具体分发方式核对；参考 [Qt 6.8 官方许可说明](https://doc.qt.io/qt-6.8/licensing.html)。Deskflow 的 OpenSSL 例外仅适用于上游明确声明该例外的文件，不适用于所有项目文件。

本次隔离构建补用了 QtTools 6.8.3：25 份许可、归因及所引用文件与官方源码归档逐字节核对，构建日志确认 Assistant 相关 litehtml 和 Gumbo 被编译。QtTools 材料单独保留，其采集不等于最终载荷许可审查。源码获取脚本固定 Deskflow、QtBase、QtTools 和 OpenSSL 的来源、大小和 SHA-256；已在独立目录实测四项下载并核对，后续对项目留存的一份 OpenSSL 3.5.9 归档另行完成[PGP 签名核验](OpenSSL源码签名核验.md)；源码下载入口本身不执行该验签。

从 QtBase、QtTools、OpenSSL 和四补丁 Deskflow 源码构建的新 Windows 核心静态部署检查涉及 17 项拟部署文件；本机静态导入未发现未解析项。VC++ 运行库交付、翻译目录、DirectX 相关文件需要性与再分发、动态加载和不同系统兼容性仍待确认；核心未启动，不能推断运行或历史核心等价。

## .NET 10.0.15 修复版材料

本次在独立目录从已验证的官方 NuGet 原始包恢复了 Windows Core、Windows Desktop 与 macOS arm64 Core 的 8 份许可、通知及 nuspec；每份与其原始 ZIP 项逐字节一致，原包 ZIP CRC 和本机 `dotnet nuget verify` 通过。它们分别记录在 `vendor/notices/dotnet-runtime-10.0.15/source-manifest.json`；验签依赖主机信任配置。历史 10.0.13 和中间验证的 10.0.14 的许可应按版本分别保留，不能替代最终包版本的通知。

历史测试包使用的 .NET 10.0.13 包含微软公告 [CVE-2026-111497](https://github.com/dotnet/announcements/issues/494) 所列受影响运行时；10.0.14 修复该项。微软另有 [CVE-2026-109475](https://github.com/dotnet/announcements/issues/500)，涉及特定 macOS/Linux HttpListener 调用场景并由 10.0.15 修复。仅凭运行时版本不能判定年年互联的实际可利用性；项目是否经过对应路径以及所有其他依赖风险均需进一步检查。不得仅凭这些条目认定 10.0.15 无其他风险。
