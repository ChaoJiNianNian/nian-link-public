# Windows 多设备测试版：独立入口方案

## 目标和边界

在保留既有发现内测 D/H 盘入口与隔离规则的前提下，新增可安装测试版所需的独立启动入口，避免要求目标设备具备指定盘符。测试资料使用用户本地资料目录下专有 `NianLinkMultiDeviceBeta/Profiles/test-<包身份>`，不迁移、不读取或覆盖正式版及旧候选资料。每个构建身份独立，因此更换构建后可能需要重新配对；不能把此行为误称为安装升级后的配对迁移。

## 实施次序

1. 先以合成路径和资料测试新入口的包身份、目录隔离、核心路径约束、已有资料归属以及路径链接拒绝；保留旧模式的 D/H 测试。随后实现入口，不放宽旧模式。
2. 设计并验证独立测试安装器，检查包清单、签名与第三方通知；使用真实已校验的输入而非伪组件。安装器与旧正式版使用不同身份及安装目录，卸载不得删除配置或其他程序。
3. 用隔离测试资料验证安装、重启和卸载，检查运行库检测和失败提示；再根据真实设备可用性验证配对、键鼠归还及断线恢复。合成测试不代表物理设备通过。

已知限制：Windows WebView2 Runtime 与匹配架构的 VC++ 运行库在干净系统上的可用性和适用许可仍需确认；打包所用历史 Deskflow/Qt 载荷的完整对应源码与发行许可尚未闭合。不能将仅完成上述路径功能当作完整可发布包。

## 入口验证边界

beta 入口从系统已知用户资料目录和包内标识推导路径，静态检查路径链接、包标识和相邻键鼠核心，并拒绝已有但未由本包认领的目录；不接受启动参数提供其他资料目录或核心位置。包标识用于一致性校验，并不是数字签名或认证。检查后创建目录之间仍有路径被同机进程并发替换的竞态窗口；这些检查不证明能抵御本机并发篡改。旧 D/H 测试入口保持原有规则。以上不代表安装器、物理设备或实际断线验收通过。

安装器的 VC++ 与 WebView2 注册表检查只判断有无注册记录，不核定最低版本、实际 DLL 或完整兼容性。每个测试构建使用不同安装目录、卸载标识和快捷方式分组；安装器不部署原 ZIP 内旧 D/H 启动脚本，亦不删除 beta 资料目录。两版并存、卸载和干净设备依赖须以实测结果为准。
