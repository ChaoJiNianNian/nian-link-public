## 目标与范围

局域网中一台主控 Windows 最多连接四台其他 Windows 或 Mac，同一时刻键鼠只交给一台；保留双向预览操作和归还、普通切换、文本剪贴板、文件传输与共享文件夹。已有一对一配置须继续可用；现有正式工具箱及真实配对数据不作为测试资料。

## 模块与顺序

1. **设备目录与信任**：每台设备唯一标识、平台、名称、独立凭证和撤销；不能共用可控制全部设备的配对令牌。
2. **键鼠会话**：基于现用 Deskflow，配置最多四个客户端，并对切换目标、状态事件和断线归还做验证。Windows 客户端与 Mac 客户端分别适配。
3. **协作通道**：预览、剪贴板、传输和共享文件夹按设备路由及隔离，预览操作同时只允许一个控制会话。
4. **显示器和界面**：按设备设置显示器输入源，在小窗选择设备；不支持 DDC/CI 的设备不得误报切屏成功。
5. **安装与验收**：隔离测试 Windows→Windows、Windows→Mac、混合多设备、断线重连、独立撤销和旧配对兼容；全部成功后才考虑正式安装包。

## 已核对的约束

- 目前 `DeskflowSessionOptions`、`DeskflowProfile`、`UnifiedSwitchCoordinator` 和 Windows 集成服务按单个远端工作；`PairedControlServer` 要求恰好两个目标并使用一个共享令牌。不得直接放宽目标数量而复用同一个令牌。
- Deskflow 官方说明服务端可向多个客户端转发输入，并支持在配置中声明多台电脑：<https://github.com/deskflow/deskflow/wiki/How-it-works>、<https://github.com/deskflow/deskflow/wiki/Server-Text-Config>。
- 所有设备名必须唯一且排除配置注入；信任必须由用户在各设备确认，旧配对不得自动授信给新设备。
- 先制作隔离的多设备 TLS 控制端原型：每台客户端用独立密钥，只能请求主机或自身，撤销与切换按顺序执行。先用 loopback 和模拟键鼠验证；尚不接现有产品、真实键鼠或现有配对。
- Windows 被控端先复用现有 Deskflow client 角色，保留独立键鼠指纹确认；邀请同时包含控制端 TLS 指纹和键鼠服务端口，不能将其中一个指纹误当作另一个通道的确认。
- 主控 Windows 的多设备凭证采用 Windows DPAPI 当前用户保护后原子保存；配对变更先持久化成功再返回凭证，启动时损坏或无法解密的资料必须报错并保留，不能清空或自动重建。Mac 侧的存储使用其平台机制，不能照搬 Windows DPAPI。
- 第一步只构建和测试隔离的多设备基础，不启用或更改正式版运行行为；不改变旧版设备的配置文件、监听或授权。

## 多设备显示器联动实施约束

- 单显示器多输入场景中，记录实际可确认的画面所在设备，不能用当前键鼠焦点代替：预览接管、外部按钮和切屏失败都会使二者不同。画面来源未知、映射不完整或显示器身份有歧义时停止自动切屏，并提示用户先确认。
- 将主机及每台客户端检测到的显示器和实际报告的接口交给用户选择；只接受允许列表内的接口，禁止默认猜测输入编号。显示器身份不一致或接口重复时不启用联动。
- 常规切换先用原子键鼠焦点交接和修订号复核，再由当前画面所在电脑发出 DDC 命令。非主机的 DDC 指令须走与该设备单独配对、认证并加密的通道；客户端必须核对本地已确认的显示器和接口，不能接受任意硬件命令。
- 远程命令须带操作标识、有效期及控制状态版本，重复或过期命令拒绝；一次只允许一个切屏操作，不能在旧命令可能仍会执行时盲目发送新命令。断线或超时应报告结果未知，并暂停自动切屏直至核实实际画面。
- 预览接管及归还不会产生切屏请求。仅当能可靠确认实际输入时更新画面状态；驱动接受命令或不可靠的非活动链路读数不得当作物理切换成功。
- 先以模拟显示器和断线、延迟、重复消息测试以上状态机，接通两端后，再在独立候选中实测真实显示器；未完成前保留原正式版，不把仅键鼠切换标作画面也已切换。

## 三台电脑与三块屏幕的扩展（2026-11-09）

- 用户已确认：台式机为主控并连接一块 27 寸屏幕；Mac 目前连接 16 寸外接屏，未来计划再连接台式机共用的那块 27 寸屏幕；Windows 笔记本当前没有外接屏、以后可能添加。另一块 27 寸的连接情况未说明，不能自动分配。三台电脑共享一套键鼠；当 Mac 将共用屏实际接好并完成接口确认后，普通台式机/Mac 切换可联动该屏幕，Mac 的 16 寸屏幕无需切换输入；未接好以前各自屏幕保持原连接。笔记本当前按独立画面处理。
- 键鼠控制以电脑为目标；显示器联动以物理屏幕为目标。某台电脑可以连接多个屏幕，一块外接屏幕也可以连接多台电脑；不同屏幕即使输入编号相同也互不冲突。笔记本内屏不能通过 DDC 切换到其他电脑。
- 先新增不接硬件的多屏关联与切换规划：仅根据用户确认的设备、屏幕、各电脑本地显示器身份、输入接口和该屏幕当前可见电脑生成针对单屏的命令。某一屏幕来源未知、目标未接入、内屏或接口有歧义时不得发命令，不影响其他屏幕；鼠标接管预览仍不能触发物理切屏。
- 普通切换只处理用户显式启用联动、且接入目标电脑的共享屏幕：当前方案中切笔记本只交接键鼠，不动共用 27 寸；切台式机/Mac 时可处理共用 27 寸，Mac 16 寸维持不变。无 DDC 的屏幕仅给出手动切源提示。命令结果或辅助进程退出未确认前不得重复下发；预览接管不执行这一流程。
- 多屏配置单独明确用户确认的电脑与屏幕关系，受本机系统机制保护并绑定每台设备的配对身份；撤销或重新配对设备时，旧屏幕授权不能自动转给新身份。保存必须是整体原子提交，旧单屏资料保留、不自动迁移。
- 设计重点补充：Mac 未来可能同时使用 16 寸与 27 寸外接屏；预览与操作需区分“查看整台电脑桌面”和“查看指定屏幕”，不能把同一电脑的两块屏幕误当两台设备。Deskflow 的电脑布局并不提供任意物理屏幕独立摆放，应以真实能力实现并避免承诺未经验证的逐屏跨边移动。
- 源码核对发现：现有 Mac 被动采集与连续预览默认取 `CGMainDisplayID`，Windows 采集也按主显示器；之前小窗写“整个桌面”不准确。候选界面先改为“默认画面”并移除尚不可用的下拉提示。按屏幕选择、断线/屏幕重排后重选、非主屏接管的指针可见性尚未实现或实机验证。
- 本轮已增加不操作硬件的多屏拓扑、逐屏状态和受保护配置模型；验证了三台设备可连接多个物理屏幕、内屏不会切换输入、每块屏幕可独立报告未确认，以及配对被撤销后旧屏幕配置不会转给新身份。没有自动读取用户的旧配置，也没有把这些模型接成完整的多屏切换或预览功能。
- 共用屏模拟链路已接入按配对设备隔离的认证传输，逐屏确认焦点与版本；切屏操作未确认时阻止会话销毁。未送达命令过期后释放并保留原画面状态，已送达但失去回复时继续保持未决，不重复写入。上述链路实验开关默认关闭，仍需设备端授权、界面及实体显示器验证。
- 保留已有单屏配置和正式版；不要自动把已保存的单屏配置扩展为三屏，也不要把 Deskflow 按电脑划分的键鼠区域伪装成已实现的单屏自由排列。连接方式确认后再决定交互、迁移和硬件执行的具体规则。
