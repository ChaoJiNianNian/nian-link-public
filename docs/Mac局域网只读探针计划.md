# Mac 局域网网卡只读探针

日期：2026-11-11。此增量将已有的 `MacSystemEvidence` 接入一个独立诊断程序，供后续在用户的 Mac 上单独编译与验证，不接入现有应用或配对流程。

## 边界和方案

- 新建 `tests/MacSystemProbe` 独立控制台项目，以同一个源码文件编译现有 SystemConfiguration 只读采集器，不复制或改变其原生调用；不引用 Mac 应用、不创建 socket、不访问钥匙串、不持久化数据、不产生网络授权。项目默认运行不采集，仅明确输入 `--run` 才尝试；任何多余或错误参数均失败，不自动重试。
- 仅 macOS 上允许真实系统采集。`--run` 在其他操作系统上失败，不调用原生函数；查询异常或无效结果返回失败码及固定简短错误，不输出系统异常细节、堆栈或部分结果。输出成功时为受限 JSON，包含协议版本和 VLAN 兼容候选的 BSD 名称列表；不输出设备名、地址、MAC、SSID、凭证或其他用户资料。返回结果只是系统的一次只读观察，不授信，也不证明接口物理性。
- 使用现有采集器的长度、类型、数量、重复值检查及 Core Foundation 所有权处理。探针进一步在序列化前校验有界、合法且不重复的 BSD 名，确保错误数据不会造成半条输出；没有网络、键鼠、界面或正式版构建依赖。
- 采集或校验失败不写成功数据；不能保证底层 stdout 在写出中断时没有残缺数据，读取方必须同时检查进程退出码为 0 和完整 JSON，不能只看是否产生输出。

## 验证

先写失败测试，覆盖默认关闭及错误参数不调用采集器、非 Mac 失败且不触发采集、合成成功格式、采集失败无部分输出、空值/过量/重复或异常名称拒绝；保留并运行采集器失败和资源释放测试。随后编译和定向回归、osx-arm64 托管交叉编译，检查该探针不在 Mac 应用项目引用图中、源码候选清单包含其必要文件，进行独立只读安全审查。

## 待验

本机 Windows 无 Mac SDK 和实际 Mac，本轮不能证明 P/Invoke ABI、符号解析、系统集合对 Wi-Fi/USB 的覆盖，也不能验证 Mac 的本地网络权限或实际发现。后续必须在经用户授权的 Mac 上以独立目录运行探针，与系统网卡只读信息对照；任何未知或不一致均保持发现关闭，不能将诊断结果当作授信。原安装、权限、钥匙串及已有设备配对不修改。

## 本机实现与验证结果

- 已新增独立 `tests/MacSystemProbe`，精确接受单个 `--run`；编译链接原采集源码，成功输出字段为 `version` 与 `vlan_compatible_candidates`，不提供真实网络授权。采集和数据校验的失败只输出固定错误，不输出异常细节。
- 先写缺失源文件的失败测试，再完成实现；隔离 Mac 边界 .NET 回归 **42 项通过、0 跳过**。不改变系统时间和真实资料。新增测试覆盖默认不调用、参数多余、非 Mac、合成结果格式、失败与非法证据，现有测试覆盖采集器的 Core Foundation 所有权与异常释放。
- `osx-arm64` 目标的托管交叉编译通过，0 警告、0 错误；该架构的 DLL 不能在 Windows x64 直接运行，首次尝试只得到程序集架构不兼容，不能作为入口测试。随后用平台无关输出在 Windows 实测：无参数退出码 2、非 Mac `--run` 退出码 3、多余参数退出码 2，均无 stdout；这不代表在 Mac 上运行过。
- 发现源码候选收集器此前虽将 Mac 测试和便携脚本列为必需文件，却未实际纳入显式收集根，现已先用失败测试复现并补齐；双时钟测试中的本机网段样例由原作者换成合成私网地址，未放宽敏感信息扫描。源码候选与项目图 Python 回归 **24 项运行、1 项本机符号链接权限跳过**，实际源码候选只读扫描通过。此扫描不是公开发布或许可证核验。
- 两次独立只读审查未发现本增量高置信阻塞。当前项目引用图证明常规 Windows、Mac 程序不引用此探针，但 Mac 打包器搬运整个 publish 目录；尚未对真实 Mac 发布包内容进行隔离验收，不得以项目图代替发布清单证明。本轮未访问 Mac 或连接设备，也没有启动网络、修改正式版或钥匙串。

## Mac 原生只读验证（2026-11-11）

- 用户确认 Mac 已开机同网。通过已有专用 SSH 身份和已保存的主机密钥严格核验后，确认目标为 macOS 27.0.1、arm64；未修改正式 App、网络或系统权限。
- 本机离线发布自包含探针到 `.artifacts/mac-discovery-probe/test-9d1a0c4267404c35b2bda34291b0eefc`；191 个扁平文件及归档/清单逐项核验。通过 SSH 在 Mac `~/Projects/nian-link-mac-probe-test-9d1a0c4267404c35b2bda34291b0eefc` 新建独立目录，校验归档及清单哈希，再以独占创建方式解包并核验每个文件；未覆盖已有目录。
- 实际 Mach-O 为 arm64；无参数退出 2，说明默认不采集。显式 `--run` 退出 0，输出的 VLAN 兼容候选为 `en0`。用系统 `networksetup` 与路由表只读交叉核对：`en0` 为 Ethernet，当前默认路由是 `en1` Wi-Fi。检查没有记录 MAC 地址或 SSID。
- 结论：此 Mac 上该系统 VLAN 候选来源不包含当前 Wi-Fi；不能据此把它用于 Wi-Fi 发现或证明全部物理网卡。该探针没有发发现数据或访问钥匙串；本机命令行运行不能替代 Mac App 系统本地网络权限或跨设备验收。后续需另查可信的 Wi-Fi 系统证据，再按权限和网络接口逐项验证。

补充只读交叉核对：系统服务顺序显示 en0 为 Ethernet、en1 为 Wi-Fi；IOKit 精确受限查询中 en1 接口链包含 Wi-Fi 控制器且系统标记内置，Wi-Fi 电源开启，默认路由为 en1。这是该 Mac 当时的系统报告，不证明其他机型、所有外接适配器或抵抗驱动伪装；接口 Up 不等于实际链路已通。一次 `ioreg` 原始输出意外含有 en0 硬件地址属性，未复制其值或保存，后续避免原样输出。未读取 SSID，也未修改设置或启动发现。

## Mac Wi-Fi 双来源只读探针计划（2026-11-11）

实际 Mac 上 VLAN 候选只含以太网，当前 Wi-Fi 未包含；新增独立 `tests/MacWifiProbe` Swift 探针，只在明确 `--run` 时使用 CoreWLAN 系统接口列表和 SystemConfiguration 的 IEEE80211 接口名，要求两份有界名单非空、合法、无重复且完全一致，输出版本及排序后的 BSD 名称。采集失败、名称冲突、系统列表与 CoreWLAN 不一致一律退出失败，不输出部分结果。不得读取 Wi-Fi 网络名、接入点标识、硬件地址，不扫描网络、不打开 socket、不访问钥匙串、不持久化或授信；这只是系统分类的交叉观察，不证明网卡物理性或排除虚拟驱动。

将名单校验放在独立纯 Swift 规则函数，以合成输入测试空、重复、越界、不合法、两侧不一致和有效多项排序；CLI 参数默认拒绝，并以静态项目检查确保应用项目不引用探针及未经允许的系统接口。首次在 Windows 先编写并运行失败的项目约束测试，再实现源码。Windows 不能编译 Swift，须由主任务在用户授权 Mac 的独立测试目录编译纯规则测试和探针，并严格验证输入/输出；命令行成功不证明 App 沙盒、系统本地网络权限、网络收发或跨机发现。

Apple 文档：CoreWLAN 建议使用 `CWWiFiClient` 返回接口对象；`SCNetworkInterfaceCopyAll` 使用系统配置集合：[CoreWLAN](https://developer.apple.com/documentation/CoreWLAN)、[SCNetworkInterfaceCopyAll](https://developer.apple.com/documentation/systemconfiguration/scnetworkinterfacecopyall%28%29)。这两种来源对不同 macOS 版本、设备和权限的覆盖未保证，遇到空值或不一致即保守失败，不请求权限或改动正式版。

### Mac Wi-Fi 双来源探针原生实测（2026-11-11）

- 主任务使用用户授权且严格固定主机密钥的既有通道，在 Mac 全新随机隔离目录核验三份 Swift 源文件 SHA-256；系统 `xcrun swiftc` 编译并运行纯规则测试通过。随后独立编译主探针，不带参数退出码为 2，明确 `--run` 输出完整 JSON、退出码为 0，结果为 `en1`。
- 该结果与此前系统只读核对的默认路由及 Wi‑Fi 设备名一致；没有读取 SSID、BSSID、硬件地址或钥匙串，也未开启发现或改变正式 App、系统设置。源文件和编译结果留在独立测试目录。
- 结果仅证明当前 Mac 的命令行进程在此次采样能通过 CoreWLAN 和 SystemConfiguration 取得一致的接口名称；不证明所有网卡覆盖、物理性、虚拟驱动抵抗、原子快照，或正式/隔离 App 的沙盒和本地网络权限。后续仍需在实际候选 App 环境和跨设备网络链路分别验证。
