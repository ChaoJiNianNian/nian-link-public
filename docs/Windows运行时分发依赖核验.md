## WebView2 Runtime

微软区分 WebView2 SDK/Loader 与目标设备运行时。正式应用需要可用的 WebView2 Runtime；安装了 Edge 浏览器本身并不能代替对 Runtime 的检查。SDK 引用版本也不是当前设备上实际运行时版本。[微软 WebView2 分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)

| 方式 | 适用考虑 |
| --- | --- |
| Evergreen 在线引导 | 安装时检测 Runtime，缺失时从微软获取引导程序；依赖网络、权限和微软服务可用性。 |
| Evergreen 离线独立安装器 | 安装器可随应用提供，适合安装阶段离线的设备；须按目标架构提供，并核对体积、来源、许可和后续更新。 |
| Fixed Version | 将特定版本随应用携带，版本与更新由应用维护；包更大，不能依赖 Evergreen 的自动更新。微软还列有特定 Windows 10/运行时版本的权限要求和网络路径限制。 |

微软对多数应用推荐 Evergreen，但自动更新可能受离线状态或管理员策略影响；应检测可用性并验证使用的 API 与实际版本兼容。安装范围和权限也取决于安装器运行上下文。[微软模式比较](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/evergreen-vs-fixed-version)

实际发行前还需核对应用所需架构的 `WebView2Loader` 如何携带、目标机器上的 Runtime 检测与缺失提示、真实版本和更新策略，并取得所选 SDK、Loader 与 Runtime 的适用许可和通知。不能把现有测试脚本的缺失提示当作完整运行时交付验证。
