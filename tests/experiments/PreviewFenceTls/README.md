# 本机 TLS 预览封存实验

这是独立研究工程，**不接入产品、不连接用户设备、不读取真实配对资料**。实验服务仅监听 `127.0.0.1`，使用临时证书、随机的合成令牌和测试内授权表。每个请求通过独立 TLS 连接；模拟动作只更新内存计数。服务端基于受限目标字段计算摘要，并从本地合成配对表校验令牌对应的可用目标，再选取内存句柄；网络请求无法注册授权。为复用已有跨所有者并发场景，表中还包含双方共享的合成目标；各自专属目标用于验证跨配对访问受拒。模型源文件从相邻 `PreviewFenceModel` 工程链接进来。

测试覆盖：先到达的 Begin 延迟入闸而 Seal 先执行、Begin 动作尚在执行时封存结果未确认、另一所有者等待、已确认归还、假令牌、错证书、不同主体和目标、过期 incarnation、旧协议拒绝、撤销、重新授权替换、丢失响应后的重试和重复动作防护。有效 A 令牌请求 B 专属目标的 Begin、Seal、Renew 受拒，且不会妨碍 B 自身的操作；换代后旧令牌失效，新令牌不扩大目标范围。乱序、重新授权及跨目标测试分别先对缺少相应保护的实验基线失败，再修正为通过。Renew 的跨目标拒绝还受到既有操作 ID 的身份和摘要匹配保护，这里不单独证明该拒绝来自配对表。

额外的回归在 A、B 均获准的公共目标上，验证 B 不能用 A 的操作编号执行 Seal/Renew；在 A 自己有权的两个不同目标上，验证 A 不能复用编号改变目标。为排除白名单提前拒绝掩盖问题，在 `tests/.work/fence-tls-binding-mutant` 的临时副本分别移除主体匹配和摘要匹配，两个实验各有 Seal 与 Renew 共两项按预期失败；原模型未被修改，完整 TLS 实验 16/16 通过。该验证只针对当前模拟身份、受限目标字段与内存模型。

在项目目录运行：

```powershell
dotnet test tests/experiments/PreviewFenceTls/PreviewFenceTls.Tests.csproj -p:UseArtifactsOutput=true -p:ArtifactsPath="$(Join-Path (Get-Location) 'tests/.work/preview-fence-tls')" --verbosity minimal
```

**限制：** 实验凭证和硬编码目标范围不是产品真实信任库；一次会话的身份映射、目标授权和临时 token 不能证明产品认证、重配、持久化或目标路由可靠。实验中的“旧进程已静止”为构造时假设，合成回调返回完成也不能证明真实 Deskflow、操作系统队列或实际键鼠动作已经停止。这个测试服务没有完整生产输入限流、协议解析或凭证生命周期，不是可直接交付的服务器。旧版本请求只在该实验服务拒绝，不能据此声称产品的旧入口已关闭。没有实现实际的断线自动恢复，不能把网络层测试通过当作安全归还或双机验收。
