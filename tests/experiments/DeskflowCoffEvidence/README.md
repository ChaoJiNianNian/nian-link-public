# Deskflow 多设备核心：编译对象取证

此目录是可携带的只读取证工具与一次本机审查摘要，不是发行构建、对应源码已完全核实、二进制一致或运行功能等价的证明。工具输入是两个独立构建目录中已经存在的 x64 COFF `.obj`；工具不编译、不执行、不更改输入，输出文件使用独占创建，不允许覆盖已有结果。

## 复现步骤

需要 Python 3。先取得有权读取的两个构建目录：一份为历史核心的编译目录，另一份为从指定上游源码及四个补丁独立重建的目录；必须单独检查构建目录的真实性和输入来源。两个目录本身以及历史核心不包含在此材料中。请在单独工作区运行：

```text
python -B -m unittest -v test_compare_coff.py
python -B compare_coff.py <旧构建目录> <新构建目录> <不存在的结果.json>
```

结果只记录两个目录下同相对路径的对象，以及单侧缺失的路径；对象输出相对路径可能含编译器编码的本机路径，**分享结果前先检查并删除本机路径信息**。不要把自动生成的 JSON 原样视作可公开文件。

## 本次已观察事实

- 固定 Deskflow 1.27.0 提交 `081f6478e654a112168879e67a41ce7d7e4ae3af` 的官方 GitHub 提交归档曾在本轮独立重新获取，SHA-256 为 `8493dfa58dbeac161a8b25d5b3cb7cb8546b5f4d99a216fcd65296b220a864f0`，与本机留存归档一致，ZIP 条目完整性检查通过。它不证明后续编译环境和源码依赖完整。
- OpenSSL 3.5.9 原始归档的本机文件大小 53,279,637 字节、SHA-256 `603f5602e2eef00d77fbd429d34dcd5822bb301757a1bc9cdb24c670f1eb859a`，与 [OpenSSL 官方发行 API](https://api.github.com/repos/openssl/openssl/releases/tags/openssl-3.5.9) 中同名资产的大小和 SHA-256 一致。此为官方元数据和本机归档哈希对照，不代表本轮完成 OpenSSL 官方 PGP 签名核验。QtBase 6.8.3 归档哈希与 Qt 官方发布的校验文件一致。
- 历史核心的现存 Ninja 构建记录指向现存历史源码目录；该源码树与固定上游及 0001—0004 补丁的独立重建树相符。该树中 844 个普通文件的当前修改时间均不晚于历史核心文件时间，时间戳可被更改，不能作为编译时未修改的决定性证明。
- 两份构建记录的 Release 核心编译和链接参数、库名称相同；共有 129 个相同相对路径的 x64 COFF 对象，单侧缺失均为零。其中 119 个有 `.text`，10 个无 `.text`；全部 46,716 个同序 `.text` 段的字节哈希相等。
- 在 95,922 条对应重定位描述中，含空代码对象时有 120/129 个对象逐符号匹配；仅对 MSVC 匿名命名空间 8 位哈希做明确归一后有 127/129 匹配，剩余 `SecureSocket.cpp.obj` 和 `MSWindowsComputer.cpp.obj` 的差异包含绝对源码路径字符串符号；两者可见路径的源码相对后缀一致。此分析没有证明两个对象的所有非代码段或外部符号内容等价。
- 旧、新构建各自的 10 个项目静态库中，各有 122 个归档成员，其完整字节分别与同一构建目录中 122 个独立对象 SHA-256 一致；此外 4 个对象直接列入核心链接命令，另 3 个是 CMake 编译器探针。核心资源文件字节一致。库、对象的这些对应关系不证明历史运行时缓存内容当时未经修改。
- 最终历史核心 SHA-256 `04ce02fb644b2e3e80a23f50077aaca1168c5a1ea520e5d45e48aa68104cfffa`；该次独立重建核心为 `98ab7501e382af081d99976c3a02a18373ae820a23f8df4f5d9a06558d03a9f5`。二者 `.rsrc` 原始字节相同，但 `.text`、`.rdata`、`.data`、`.pdata`、`.reloc` 和链接时间戳存在差异。不能将源码路径差异认定为所有二进制差异的唯一原因。

## 局限

比较器对标准 x64 COFF 对象比较 `.text`、重定位偏移/类型及符号名，并针对匿名命名空间做有限归一；未证明数据段、链接器输入、系统库、最终 PE 或执行行为一致。两次构建复用了本机 MSVC、Qt 和 OpenSSL 开发材料；外部依赖真实版本、许可及历史时刻内容仍需单独核验。它不是干净系统重建证据。修复或替换现有核心应使用独立测试构建，不能关闭或绕过现有完整性 pin，亦不能覆盖现用正式版。
