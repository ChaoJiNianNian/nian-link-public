# 授权标识隔离研究

这个工程仅在测试程序集内模拟授权标识与无动作封存，**未接入产品、服务器或自动恢复**。测试在系统临时目录 `nian-link/synthetic-vault-grant-identity` 下创建全新合成 vault，Windows 当前用户的保护器加密合成资料，不读取现用配对；测试输出不包含 token、派生值或完整设备指纹。研究程序集只为复用既有测试友元而命名为 `MultiPeerTrust.Tests`，应始终使用以下独立构建输出，不能复制到产品目录。

研究通过仅 `NIAN_FENCE_RESEARCH` 测试编译可见的受限 vault API，在授权锁内检查当前合成 token 并比较所有设备的 token；旧版 v1 出现重复时拒绝推导。受限 API 只将非 token 的设备身份快照传给研究回调，回调不重入 vault、不做 I/O。唯一匹配时，以合成 token 作 HMAC 密钥，输入带专用域的规范名称、指纹、平台和槽位，结果只保存在实验对象内；外部只收到研究枚举，不提供摘要获取或网络接口。HMAC 实现由此实验和另一真实回环服务器研究共享，两者都只在测试编译中存在。登记与授权撤销在同一把 vault 锁中排序。锁内阻塞钩子仅用于故障测试，不是产品 API；此研究不发送键鼠命令。

```powershell
dotnet test tests/experiments/VaultGrantIdentity/VaultGrantIdentity.Tests.csproj -p:NianFenceResearchIsolatedTest=true -p:UseArtifactsOutput=true -p:ArtifactsPath="$(Join-Path (Get-Location) 'tests/.work/vault-grant-research-isolated')" --verbosity minimal
```

测试覆盖：已确认授权重开而不改写 vault；撤销并用相同名称和指纹重配；旧 token、错误 token 和错误设备名被拒；锁内登记与撤销排序；等待 vault 锁期间取消不得执行研究回调；v1 重复 token 歧义拒绝；pending 事务重开后候选标识一致且在真正批准前不可登记；容量满保留旧封存；以及恢复**合成**旧备份后旧授权重新有效的反例。测试最初先以未实现的研究对象失败，后完成验证；其中 pending 测试仅覆盖未完成事务的读取重开，不代表完成了真实免文件恢复交付。

锁契约修正后定向测试 **10/10**，默认信任套件 **165/165** 且反射确认默认构建没有该研究 API，真实服务器回环研究 **12/12**；独立复审在实验范围内未发现新的确定性死锁或泄露。取消测试证明等待锁期间取消不会执行回调；回调一旦开始，取消不撤销已经进行的同步操作。

**重要边界：** 这个值由既有随机 token 派生，并不是独立生成、持久保存的新授权代次。恢复旧备份会复活旧 token 和同一标识；测试明确复现了这一限制。没有反回滚锚点、跨进程锁存、可信网络范围、可验证原生队列封存或任何真实设备验证；旧版并行使用及外部替换 vault 也不能由该模型安全协调。`Begin` 返回研究枚举只表示内存模型未拒绝，绝非允许真实控制的授权。只有后续单独设计严格版本与迁移、解决上述边界并验证全链路后，才可考虑产品接入。

测试使用随机子目录及合成凭证；实验结束后可能留下临时资料，不要将其提交或用于正式配对。
